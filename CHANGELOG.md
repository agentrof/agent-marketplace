A cancellation is final: its Items are cancelled and a second cancellation is refused, so after such an invalidation nothing could publish a Review again, and the cancelled Delivery could never reach the target through its PR.

A Delivery whose PR was recorded while it stayed in review is closed the same way, the coordinator's own commits, such as the reopen commit, never count as that merge, and a shallow clone or a failed Git query is reported as a finding instead of an unmerged Delivery.
- On native Windows the Delivery coordinator now hands Git the blobs and commit messages it writes as exact UTF-8 bytes, as on every other host. It wrote them through text-mode pipes, which there end every line with CRLF and encode in the ANSI code page, so push-item refused every started Item as a changed control, the Architecture stamp check failed on the activated record, projection-only merges stayed unmerged, and a record or message holding a character the code page lacks, such as ş, ğ or ı, could not be written at all.
- On native Windows the Delivery coordinator now hands Git every repository path with forward slashes, as on every other host, instead of backslash paths that name no file in a Git tree, and compares the paths Git returns in the same form; the commit check behind stage receipts names its package the same way.
- The generated Delivery map now always ends with one newline, the ending the vault relation render gives every note, so a later unrelated change no longer carries a newline-only rewrite of the map a Delivery publication produced.
- The Delivery coordinator now reads the paths it takes from Git in its pending-path, index-flag, Architecture, stamp, path-claim and waits-for checks as Git's exact NUL-separated bytes, so a name holding a carriage return, such as a macOS `Icon\r`, no longer comes back with a newline; and a cancellation revert takes every path literally, so an Item's change to a path starting with `:` is restored instead of deleted.
- The Delivery coordinator now reads the paths a target refresh, a cancellation revert and an Item push list from Git as NUL-separated bytes decoded as UTF-8, instead of the quoted form Git prints for a name outside ASCII, so a target change to a claimed path such as src/giriş/kayıt.py is refused and a cancelled Item's change to such a path is reverted, where both went through unseen before; the setup check names such force-added local files as they are.
- On native Windows the Delivery coordinator, compiler and GitHub adapter now read what Git and gh print as UTF-8, as on every other host, instead of in the ANSI code page, so notes, map rows, commit trailers and paths that hold characters outside ASCII, such as an em dash or ş, ğ and ı, no longer read back as mojibake from a commit; the GitHub adapter also hands gh its input as UTF-8 bytes.
- On native Windows the Delivery coordinator now locks its Item writer, pull request and target-update receipts through msvcrt, as setup and Experience transactions already lock there, instead of failing every step that starts an Item or writes a provider or target receipt; the lock still ends with the process that holds it, and all three take it through one shared helper.

A refusal with no matching declared code still reports DELIVERY_INPUT_INVALID.
- The Delivery coordinator's result envelope and the Delivery compiler's JSON results now reach standard output as UTF-8 bytes on every host. On native Windows a redirected standard output encodes in the ANSI code page, so a result that named a letter it lacks, such as ş, ğ or ı in a path or message, raised UnicodeEncodeError after the command had already run and left its caller without a result.
