- invalidate-delivery-review now refuses the cancellation Review of a cancelled Delivery under DELIVERY_CANCELLATION_INVALID. A cancellation is final: its Items are cancelled and a second cancellation is refused, so after such an invalidation nothing could publish a Review again, and the cancelled Delivery could never reach the target through its PR.
- A Delivery cancelled after its PR was opened now gives that PR the published cancellation Review as its body when open-pr records the cancellation, whether it adopts the PR or a new PR intent finds it, instead of leaving the body that still states the earlier approval. The GitHub adapter updates the body through the pull request REST endpoint with gh api, which sends the body alone and needs no read access to the PR's reviewers or projects.
- Recording a Delivery PR now moves the Delivery to awaiting_merge in the PR head itself, and the Delivery compiler reports it as merged once the current branch reaches a merge of that exact recorded head, including through a target refresh, so a merged Delivery keeps its pinned historical sources instead of failing its check after a later backlog revision. A Delivery whose PR was recorded while it stayed in review is closed the same way, the coordinator's own commits, such as the reopen commit, never count as that merge, and a shallow clone or a failed Git query is reported as a finding instead of an unmerged Delivery.
- On native Windows the Delivery coordinator now hands Git the blobs and commit messages it writes as exact UTF-8 bytes, as on every other host. It wrote them through text-mode pipes, which there end every line with CRLF and encode in the ANSI code page, so push-item refused every started Item as a changed control, the Architecture stamp check failed on the activated record, projection-only merges stayed unmerged, and a record or message holding a character the code page lacks, such as ş, ğ or ı, could not be written at all.
- On native Windows the Delivery coordinator now hands Git every repository path with forward slashes, as on every other host, instead of backslash paths that name no file in a Git tree, and compares the paths Git returns in the same form; the commit check behind stage receipts names its package the same way.
- The generated Delivery map now always ends with one newline, the ending the vault relation render gives every note, so a later unrelated change no longer carries a newline-only rewrite of the map a Delivery publication produced.
- The Delivery coordinator now reads the paths it takes from Git in its pending-path, index-flag, Architecture, stamp, path-claim and waits-for checks as Git's exact NUL-separated bytes, so a name holding a carriage return, such as a macOS `Icon\r`, no longer comes back with a newline; and a cancellation revert takes every path literally, so an Item's change to a path starting with `:` is restored instead of deleted.
- The Delivery coordinator now reads the paths a target refresh, a cancellation revert and an Item push list from Git as NUL-separated bytes decoded as UTF-8, instead of the quoted form Git prints for a name outside ASCII, so a target change to a claimed path such as src/giriş/kayıt.py is refused and a cancelled Item's change to such a path is reverted, where both went through unseen before; the setup check names such force-added local files as they are.
- On native Windows the Delivery coordinator, compiler and GitHub adapter now read what Git and gh print as UTF-8, as on every other host, instead of in the ANSI code page, so notes, map rows, commit trailers and paths that hold characters outside ASCII, such as an em dash or ş, ğ and ı, no longer read back as mojibake from a commit; the GitHub adapter also hands gh its input as UTF-8 bytes.
- On native Windows the Delivery coordinator now locks its Item writer, pull request and target-update receipts through msvcrt, as setup and Experience transactions already lock there, instead of failing every step that starts an Item or writes a provider or target receipt; the lock still ends with the process that holds it, and all three take it through one shared helper.
- Delivery coordinator refusals now report the finding code the result contract declares for them, such as DELIVERY_PR_STATE_INVALID, DELIVERY_PR_HEAD_BASE_MISMATCH, DELIVERY_MERGE_PROOF_INVALID, DELIVERY_FENCE_MODE, DELIVERY_ITEM_NOT_READY or DELIVERY_WORKTREE_UNSAFE, instead of DELIVERY_INPUT_INVALID, and keep their message. The target refresh and activation refusals that began with claimed_source_violation or target convergence required now report DELIVERY_TARGET_SOURCE_VIOLATION and DELIVERY_TARGET_CONVERGENCE_REQUIRED. A refusal with no matching declared code still reports DELIVERY_INPUT_INVALID.
- The Delivery coordinator's result envelope and the Delivery compiler's JSON results now reach standard output as UTF-8 bytes on every host. On native Windows a redirected standard output encodes in the ANSI code page, so a result that named a letter it lacks, such as ş, ğ or ı in a path or message, raised UnicodeEncodeError after the command had already run and left its caller without a result.
- Approving a Delivery Review now keeps what its author wrote in each section, so the published Review and the Delivery PR carry the outcome, deviations, evidence and follow-up decisions instead of placeholder text.
- The Windows CI job now runs the Delivery compiler and coordinator test modules, with a timeout sized for their Git process count; the POSIX assumptions those modules made about file modes, symlink rights, file names, path separators and line endings now hold on native Windows or skip there with their reason.
- On native Windows the Delivery scripts now write the pinned Definition of Done path and the links in the Delivery map, execution plan, Item evidence, Delivery Review and cancellation Review with forward slashes, as on every other host, so the links resolve in the vault.

It kept the body it was opened with, so the provider showed the earlier Review while the PR head carried the new one. This extends the body update that a cancellation already gets to every such PR.

## 0.4.1

- The release finalizer cleans up merged feature branches under the prefix each registered host adapter declares, claude/ for Claude Code and codex/ for Codex, instead of codex/ alone; unmerged, unbounded, duplicate and undeclared branch names are still refused.
- A Delivery now reads an Item ref as its own only when the tip's Agentrof-Delivery trailer names it: target refresh no longer re-issues another Delivery's claim of the same Story, refresh and cancellation no longer fail with a raw Git error on it, scope revision stays open, and claim-items names the Delivery that holds the Story.
- Once merge-pr or verify-merge proves a Delivery's merge, the coordinator deletes its Integration ref and the Item refs of its integrated Stories, so a project keeps only the Fence instead of one branch per delivered Story; claim-items and waits_for read a merged Delivery's package from the target, and verify-merge removes the refs earlier releases left.
- Setup's package refresh returns tracked files that writers before v0.4.0 left owner-only (0600) in the workspace config, the governed vault and the managed root files to group and other read, as the umask allows and never with a write bit, and setup check reports them as drift; the vault guard accepts that read-only widening of compiler-owned Experience state and still restores every other mode change.
